# Источник 3: Александринский театр

**Статус:** active (прототип).

- Сайт: https://alexandrinsky.ru/afisha-i-bilety/
- Тип источника: серверный HTML (афиша есть в исходном коде страницы)
- Инструменты: `httpx` + `BeautifulSoup4/lxml`

## Запуск

```bash
pip install -r requirements.txt
python parser.py
python parser.py > data/sample_output.json   # сохранить пример результата
```

Нужен Python 3.10 или новее.

## Что выводится

Список объектов `Event` в JSON. Один сеанс = один объект.

| Поле | Что это |
|---|---|
| `title` | название мероприятия |
| `starts_at` | дата и время (без часового пояса) |
| `venue` | сцена и зал, например "Новая сцена, Черный зал" |
| `description` | описание из карточки |
| `url` | страница спектакля |
| `ticket_url` | ссылка на сеанс (`?ID_EVENT_SB=...`), если есть |
| `tickets` | `link_available` или `unknown` |

## Как работает

1. Находит заголовки `h4` со ссылкой на `/afisha-i-bilety/`. Привязка к
   заголовку, а не к CSS-классам.
2. Определяет карточку: родитель заголовка, внутри которого ещё нет
   других спектаклей.
3. Берёт сцену и зал из текста перед заголовком, описание из абзацев.
4. Собирает даты из списков `li`: на каждую дату отдельное событие.

## Особенности источника

- **Нет года в датах** ("19 ноя 18:00"). Год угадывается: дата больше
  чем на 60 дней в прошлом считается следующим годом.
- **ID сеанса (`ID_EVENT_SB`) есть не у всех.** Ссылки с ID появляются
  в полном списке дат (блок "еще"), у карточек с короткими списками их нет.
- **Наличие билетов на афише не указано.** Есть только ссылка на сеанс,
  поэтому `tickets` бывает `link_available` или `unknown`.
- Афиша продублирована в двух вариантах вёрстки (карточки и слайдер).
  Лишний вариант отсекается привязкой к `h4`.
- В афише есть не только спектакли, но и экскурсии. Отдельного поля
  для типа события нет.

## Как отличать уже известные события (не реализовано)

Предлагаемый ключ: `ID_EVENT_SB`, если он есть, иначе
`slug спектакля + дата и время`. Ограничение: если у сеанса нет ID и
изменилось время, он будет выглядеть как новое событие.

## Ограничения и что не проверено

- Не проверены `robots.txt`, условия использования, поведение сайта при
  частых запросах.
- Не проверено, показывает ли страница весь репертуар или только часть
  (возможна подгрузка), и есть ли страница календаря с полным списком.
- Нет повторных попыток запроса и защиты от блокировок. При ответах
  403/429 скрипт просто падает с ошибкой.

# Источник 4: БДТ им. Товстоногова

**Статус:** active (прототип).

- Сайт: https://bdt.spb.ru/afisha/ (по месяцам: `?month=12`)
- Тип источника: серверный HTML (афиша есть в исходном коде страницы)
- Инструменты: `httpx` + `BeautifulSoup4/lxml`

## Запуск

```bash
pip install -r requirements.txt
python parser.py                 # текущий месяц
python parser.py --month 12      # афиша на декабрь
python parser.py > data/sample_output.json   # сохранить пример
```

Нужен Python 3.10 или новее. За один запуск разбирается один месяц.

## Что выводится

Список объектов `Event` в JSON. Один сеанс = один объект.

| Поле | Что это |
|---|---|
| `title` | название спектакля |
| `starts_at` | дата и время (без часового пояса) |
| `venue` | сцена и адрес, например "МАЛАЯ СЦЕНА БДТ наб. Фонтанки, 65" |
| `description` | строки под названием (автор, режиссёр, состав) |
| `url` | страница спектакля |
| `ticket_url` | ссылка на покупку (Ticketland), если есть |
| `tickets` | `link_available` или `none` |

## Как работает

1. Афиша состоит из строк-дат (`div.afisha-row`), в каждой один или
   несколько спектаклей (`.cell-data > .d-flex`).
2. Дата ("19/11") запоминается и действует для следующих блоков, если
   у них своей даты нет.
3. Из блока берутся название, время ("Начало в 19:00"), сцена и
   ссылка Ticketland.
4. Перенесённые и отменённые спектакли (пометка "ВНИМАНИЕ: Перенос" или
   "ВНИМАНИЕ: Отмена") пропускаются.

Селекторы вынесены в код как строки в `parse_bdt` и `parse_bdt_block`,
их нужно править при изменении вёрстки.

## Особенности источника

- **Нет года в датах** ("19/11"). Год угадывается: дата больше чем на
  60 дней в прошлом считается следующим годом.
- **Перенос и отмена стоят в афише обычными строками.** Новая дата
  переноса в этой строке указана текстом, но парсер её не разбирает.
- **Время может расходиться с Ticketland.** Например, на сайте
  "Начало в 15:00", а в ссылке Ticketland метка 13:00. Берётся время
  из "Начало в".
- **ID сеанса есть в ссылке Ticketland** (`..._p_28781027`), но в
  выводе отдельным полем не хранится.
- Над названием у части спектаклей есть строка-подпись ("Хореодрама",
  "ВИДЕОВЕРСИЯ СПЕКТАКЛЯ"). В `title` она не попадает, отдельного
  поля для типа нет.
- Наличие мест не проверяется: только есть ли ссылка на покупку.

## Как отличать уже известные события (не реализовано)

Предлагаемый ключ: ID сеанса Ticketland (число после `_p_` в ссылке),
если ссылки нет, то `slug спектакля + дата и время`.

## Ограничения и что не проверено

- Не проверены `robots.txt`, условия использования, поведение сайта при
  частых запросах.
- Не обработан случай, когда пометка отмены стоит вне блока спектакля:
  такой спектакль попадёт в вывод с `tickets: none`.
- Нет повторных попыток запроса и защиты от блокировок. При ответах
  403/429 скрипт просто падает с ошибкой.

# Источник 4: Санкт-Петербургская филармония


- Сайт: https://www.philharmonia.spb.ru/afisha/
- Тип источника: серверный HTML (события есть в исходном коде страницы;
  продолжение списка подгружается кнопкой "ещё" через AJAX)
- Инструменты: `httpx` + `BeautifulSoup4/lxml`

## Запуск

```bash
pip install -r requirements.txt
python parser.py                # текущий месяц
python parser.py 12             # декабрь текущего года
python parser.py 3 2027         # март 2027 года
python parser.py > data/sample_output_philharmonia.json   # сохранить пример результата
```


## Что выводится

Список объектов `Event` в JSON. Один сеанс = один объект.

| Поле | Что это |
|---|---|
| `title` | название мероприятия |
| `starts_at` | дата и время (без часового пояса) |
| `venue` | зал: "Большой зал", "Малый зал", "Музиторий" |
| `description` | подзаголовок (фестиваль), исполнители, программа, организаторы |
| `url` | страница события (`/afisha/<id>/`) |
| `ticket_url` | всегда `null` (покупка открывает JS-виджет, ссылки нет) |
| `tickets` | `link_available`, `unknown` или `none` |

## Как работает

1. Берёт месяц из аргументов командной строки (`[месяц [год]]`), по
   умолчанию — текущий.
2. Запрашивает афишу месяца серверным фильтром `?year=<сезон>&month=<м>`.
   **year — это год сезона** (сезон длится с сентября по июнь): март 2027
   запрашивается как `?year=2026&month=3`, перевод делается в коде.
3. Находит блоки `div._item` внутри `div.it-afisha-list` — каждый блок
   это одно событие. Служебные блоки (разделители, спонсоры) отсеиваются:
   у них нет даты или заголовка.
4. Дату и время берёт из `div._date_from`: день, месяц словом, год, время.
5. Место — текст ссылки `div._hall`.
6. Описание склеивается из `._preview`, `._ansambles`, `._persmain`,
   `._programm` и `._organisers`; у многодневных событий добавляется
   время окончания из `._date_to`.
7. Статус билетов — по блоку `._sale`: кнопка "Купить билет" →
   `link_available`; "Все билеты проданы" / "Билеты не продаются" →
   `none`; иначе → `unknown`.
8. Если месяц не поместился на одну страницу, листает кнопкой "ещё"
   (`div.more`, URL следующей страницы в атрибуте `ajax`, вида
   `?PAGEN_1=N`). На всякий случай события дополнительно фильтруются
   по запрошенному месяцу.

## Особенности источника

- **Билеты продаются через JS-виджет**: у события кнопка
  `button.__buy[data-epts-event-id]`, отдельного URL нет, поэтому
  `ticket_url` всегда `null`, а статус определяется по тексту блока.
- **Фильтр по месяцу серверный**: весь месяц приходит одной страницей
  (ноябрь 2026: 75 событий, кнопки "ещё" нет). Обход `PAGEN_1` оставлен
  на случай, если большой месяц перестанет влезать на одну страницу.
- **У события есть стабильный числовой id**: в CSS-классе блока
  (`__id_1091278`) и в URL (`/afisha/1091278/`).
- **Многодневные события** (например, "Ночь музеев"): начало в `_date_from`,
  окончание в `_date_to`; в `starts_at` попадает только начало, окончание
  дублируется текстом в `description`.

## Как отличать уже известные события (не реализовано)

Ключ: числовой `id` события (класс `__id_<число>` или URL `/afisha/<id>/`).
Один `id` может давать несколько сеансов (дат) — тогда ключ `id + starts_at`.

## Ограничения и что не проверено

- Нет повторных попыток запроса и защиты от блокировок. При ответах
  403/429 скрипт просто падает с ошибкой.
- Не проверены `robots.txt`, условия использования, поведение сайта при
  частых запросах.
- Проверено 22.11.2026: текущий месяц (ноябрь 2026) — 75 событий;
  `3 2027` — март 2027, 36 событий; месяц целиком помещается на одну
  страницу.

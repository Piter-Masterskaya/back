# Источник 18: Базилика Св. Екатерины (bazilika_catherine_18)


- Сайт: https://bazilika-catherine.ru/concerts/
- Тип источника: серверный HTML, но расписание публикуется **картинками**
  (постерами). Текстового списка событий на странице нет.
- Инструменты: `httpx` + `BeautifulSoup4/lxml`

## Запуск

```bash
pip install -r requirements.txt
python parser.py
```

Результат сохраняется в `data/example_output.json`, постеры — в
`data/posters/`.

Нужен Python 3.9 или новее (используется `zoneinfo`).

## Что выводится

Список объектов `Poster` в JSON. Единица события здесь — **постер**,
а не сеанс: названия и даты находятся внутри картинки.

| Поле | Что это |
|---|---|
| `image_url` | ссылка на оригинал картинки (`/uploads/...`) |
| `image_hash` | SHA-256 содержимого, `sha256:...` — отпечаток постера |
| `venue` | название площадки, константа |
| `url` | страница-источник постера |
| `ticket_url` | всегда `null` — прямых ссылок на покупку в HTML нет |
| `tickets` | `unknown` — статус билетов по постеру не определить |
| `source` | id источника, константа `bazilika_catherine_18` |
| `collected_at` | ISO 8601, когда страница была скачана |

## Как работает

1. Сайт собран на конструкторе uKit: все картинки лежат в виджетах
   `div.ul-widget[type="uImage"]`, высоту задаёт внутренний `div[height]`.
2. Страница разбита на секции в фиксированном порядке: заголовок
   «КОНЦЕРТЫ» -> постеры -> заголовок «ЭКСКУРСИИ» -> фото храма и контакты.
   Секция афиши берётся **срезом виджетов между двумя заголовками**, поэтому
   статичное фото храма внизу страницы и баннеры партнёров (200px) в выборку
   не попадают, даже если админ их заменит.
3. Берётся `<img src>` (оригинал без масштабирования), а не `srcset`:
   у него стабильное имя файла и стабильный хэш.
4. Картинка скачивается, считается SHA-256. Хэш входит в имя файла:
   при замене постера появится новый файл, старый останется на диске
   как история изменений.

## Особенности источника

- **Единица данных — постер, а не сеанс.** Внутри одного постера может быть
  несколько концертов. Для движка сравнения «относительно вчера» изменение
  афиши = появился/заменился/исчез постер. Уведомление звучит как
  «обновилась афиша, вот постер», а не «добавлен концерт X».
- **Постеры двух типов** (выяснено экспериментально, см. `ocr_experiment.py`):
  - **Календарная сетка месяца** — таблица «дата + название + исполнитель».
    OCR распознаёт хорошо: даты, названия («Орган и дудук при свечах»,
    «Киномузыка на органе»), имена исполнителей и каналы продажи
    (Билетер, Яндекс Афиша, билеты в церковной лавке).
  - **Арт-постер спектакля** — дизайнерская афиша с декоративными шрифтами.
    OCR почти не работает: вытаскиваются только обрывки («Ludus Danielis»,
    «Действо о Данииле»).
- **Билеты продаются на агрегаторах** (Билетер, Яндекс Афиша и т.д.), но
  ссылок на них в HTML афиши нет — они упомянуты только внутри картинок.
  Коммерческие концерты Базилики в агрегаторах видны полностью, но это
  отдельные источники реестра, а не этот.
- **На странице только текущий месяц** и только будущие события: прошедшие
  концерты исчезают с афиши. Исчезновение постера — валидное изменение,
  а не ошибка парсинга.

## Как отличать уже известные события

Предлагаемый ключ: `source + image_url` (URL оригинала стабилен, имена файлов
уникальны) с контролем `image_hash`:

- новый `image_hash` при новом URL — добавлен постер;
- тот же URL с другим `image_hash` — картинка перезалита (редко, uKit
  обычно генерирует новое имя файла);
- хэш исчез из выборки — постер снят.

```
bazilika_catherine_18 + full_6AH2tyjJ.jpg + sha256:e5ee805...
```

## OCR (эксперимент, не входит в основной пайплайн)

`ocr_experiment.py` — **локальный эксперимент для Windows** с установленным
Tesseract (UB Mannheim). В DevContainer/CI не запускается: там Tesseract
ставится отдельно (`apt-get install -y tesseract-ocr tesseract-ocr-rus`).

Скрипт переводит постеры в ч/б (с инверсией тёмного фона) и печатает
сырой распознанный текст. Вывод эксперимента:

- календарные сетки распознаются достаточно хорошо для извлечения дат
  и названий регулярками — как вариант развития;
- арт-постеры OCR не осиливает — для них детекция изменений по хэшам
  остаётся единственным рабочим механизмом.

## Ограничения и что не проверено

- Если админ добавит постер **вне** секции «КОНЦЕРТЫ» (выше заголовка или
  после «ЭКСКУРСИЙ»), парсер его не увидит. Сейчас все постеры лежат в
  секции, но при обновлении вёрстки стоит проверить глазами.
- OCR-извлечение дат в общем формат `Event` не доведено: текст из сеток
  содержит опечатки («присвечах», «на оргаме»), требует ручной выверки.

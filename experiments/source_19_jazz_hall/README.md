# Источник 19: Филармония джазовой музыки

- Сайт: https://jazz-hall.ru/afisha/
- Тип источника: серверный HTML (карточки афиши есть в исходном коде страницы)
- Инструменты: `httpx` + `BeautifulSoup4/lxml`

## Запуск

```bash
pip install -r requirements.txt
python parser.py
```

Результат сохраняется в `data/example_output.json`.

Нужен Python 3.9 или новее (используется `zoneinfo`).

## Что выводится

Список объектов `Event` в JSON. Один сеанс = один объект.

| Поле | Что это |
|---|---|
| `title` | название мероприятия |
| `starts_at` | дата и время в ISO 8601, UTC |
| `venue` | зал, например «Большой зал» или «Колизей-Арена» |
| `description` | описание из карточки (может быть `null`) |
| `url` | страница события (`/afisha/<id>/`) |
| `ticket_url` | всегда `null` — прямой ссылки на покупку в HTML нет |
| `tickets` | `link_available` или `none` |
| `source` | id источника, константа `jazz_hall_19` |
| `collected_at` | ISO 8601, когда страница была скачана |

## Как работает

1. Находит активную вкладку месяцев (`label.afisha__tabs-label-active`) и берёт
   месяц и год из её атрибута `data-date="24.11.2026"`. Так карточки не
   попадают не в тот месяц.
2. Перебирает карточки `div.afisha__list-item`: день — из блока даты,
   время — из первого `<p>` контента.
3. Среди всех `<p>` контента время отфильтровывается по шаблону `ЧЧ:ММ`,
   последний оставшийся `<p>` — зал, всё между временем и залом — описание.
   Порядок не съезжает, даже если описания у концерта нет.
4. Время событий московское, переводится в UTC перед сохранением.

## Особенности источника

- **Билеты через JS-виджет profi.ticket.** Прямой ссылки на покупку в HTML
  нет: кнопка «Купить» рендерится скриптом. Статус бинарный: есть кнопка —
  `link_available`, нет кнопки — `none`. Цены и «продано» на странице афиши
  не видны.
- **В статичном HTML — только активный месяц.** Вкладки «декабрь» и «январь»
  подгружаются скриптом (сайт на Битриксе), поэтому пока парсер видит один
  текущий месяц. Как появится XHR-запрос с параметром месяца — можно
  добавить флаг `--month` по образцу парсера БДТ.
- **Сайт показывает только будущие события.** Прошедшие концерты исчезают
  с афиши: для движка сравнения «относительно вчера» исчезновение события —
  валидное изменение, а не ошибка парсинга.
- Иногда один вечер — два сеанса с разным временем (два объекта с одним URL).

## Как отличать уже известные события

Предлагаемый ключ: `source + url + starts_at`.

```
jazz_hall_19 + https://jazz-hall.ru/afisha/3101/ + 2026-11-24T16:00:00+00:00
```

`url` внутренний и стабильный (числовой ID события), поэтому ключ надёжен.
Ограничение: если событие ушло из афиши и вернулось — оно посчитается новым.

## Ограничения и что не проверено

- Не проверены `robots.txt`, условия использования, поведение сайта при
  частых запросах.
- Нет повторных попыток запроса и защиты от блокировок. При ответах
  403/429 скрипт падает с ошибкой (`SystemExit`).
- Не проверено, доступна ли вкладка следующего месяца обычным GET-запросом.

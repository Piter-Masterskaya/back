# Эксперимент: Парсер источника №11 — Музей театрального и музыкального искусства

- **Источник:** https://theatremuseum.ru (в старых ссылках `/afisha`, актуальный раздел афиши — `/event`)
- **Подход:** Статический HTML (SSR, кодировка `UTF-8`), HTTP-клиент `httpx` + `BeautifulSoup4 (lxml)` + валидация `Pydantic`.

## Запуск и проверка дедупликации

```bash
cd experiments/theatremuseum_11
python -m venv .venv
source .venv/bin/activate  # для Windows: .venv\Scripts\activate
pip install -r requirements.txt
python parser.py
```

- **Первый запуск:** парсер собирает мероприятия, сохраняет их в `data/sample_output.json`, а их идентификаторы записывает в `data/seen_ids.json`.
- **Повторный запуск:** при повторном вызове `python parser.py` все уже известные события пропускаются с записью в лог (`Пропуск уже известного мероприятия`), а в `data/sample_output.json` попадают только новые. Чтобы заново протестировать полный сбор с нуля, удалите файл `data/seen_ids.json`.

## Особенности источника и выявленные ограничения

1. **Структура URL, фильтров и пагинации:**
   - Афиша отдаётся сервером в HTML без обязательного JS-рендеринга.
   - Фильтрация по датам работает через GET-параметр `data_find=DD.MM.YYYY - DD.MM.YYYY`.
   - **Находка по пагинации:** параметр `?page=2` возвращает те же 10 карточек, что и первая страница (дедупликация успешно отсекла дубли при переходе на вторую страницу). Для продакшн-версии нужно дополнительно проверить реальный GET-параметр переключения страниц (например, `PAGEN_1` или `list`).
2. **Особенности данных в карточках:**
   - В общей ленте афиши часто указан **диапазон дат** проведения цикла или выставки (например, `25.11.2026 - 30.11.2026`), а точное время сеанса и ссылка на виджет покупки билетов (`tickets.theatremuseum.ru`) находятся внутри детальной страницы `/event/<slug>`.
   - У музея 6 филиалов (Театральный музей, Шереметевский дворец, Музей-квартира Римского-Корсакова и др.), название площадки указано текстом в карточке без точного уличного адреса (адреса придётся маппить справочником в продакшне).
3. **Дедупликация при повторном запуске:**
   - Реализована через детерминированный SHA-256 хеш от связки `canonical_url + date_time`, сохраняемый в `data/seen_ids.json`.
   - **Ограничение:** Если музей продлит выставку и изменит строку диапазона дат (например, с `25.11.2026 - 30.11.2026` на `25.11.2026 - 15.12.2026`), хеш изменится и событие определится как новое (в продакшне потребуется `upsert` по `url` с обновлением поля даты окончания).
